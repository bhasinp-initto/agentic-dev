# Phase 6 — Queue + Circuit Breaker + Orchestrator Design

**Date:** 2026-05-21 · **Phase:** P6/8 · **Umbrella spec:** §10 (queue model), §11 (circuit breaker), §12 (escalation mechanics), §22 (wake-up interval)

## 1. Intent

P6 wires the autonomous orchestrator that drives the entire P3 → P4 → P5 pipeline goal-by-goal across an approved queue. It manages state transitions on `queue.yaml` (goal status: `approved` → `running` → `completed | halted`), the `state.json` circuit breaker (`idle | running | halted | completed`), the auto-fix loop (P5's `auto-fix-queue/<id>.json` → re-dispatch implementer; cap 2 rounds), worktree cleanup on success, and ScheduleWakeup-based overnight progression.

## 2. Goals

- **G1** — State transition helpers (`bin/queue-set-status.sh`, `bin/circuit-breaker.sh`) that atomically update queue.yaml and state.json with schema validation.
- **G2** — `_advance-goal` skill: one full pipeline pass on a single approved goal (init worktree → implementer → gates → reviewer → route concerns / auto-fix loop / escalate / mark complete + cleanup).
- **G3** — Auto-fix loop integration: when `_run-reviewer` writes `auto-fix-queue/<id>.json` with only mechanical concerns, orchestrator re-dispatches implementer with the concerns as inputs; re-runs gates + reviewer; caps at 2 rounds before escalating.
- **G4** — `_run-orchestrator` skill: top-level loop over the queue. Picks first `approved` goal; runs `_advance-goal`; on clean exit, advances to next; on halt, sets circuit breaker, generates escalation, exits.
- **G5** — User-facing `/agentic-dev:start` (begin a queue run with optional `--until` time/duration) and `/agentic-dev:resume` (after a halt, decide resume/skip/address/replan/abort).
- **G6** — ScheduleWakeup-driven overnight progression: orchestrator can pause itself between goals and self-resume.
- **G7** — Cost policy compliance: deterministic tests for state helpers + structural tests for skills; ZERO `claude -p` in P6.

## 4. State machine

### Goal-level (`queue.yaml`)
```
approved ──> running ──> completed (clean)
                    \──> halted (gate/judgment/blocking/spec-drift)
                    \──> abandoned (human decision)
```

### Circuit breaker (`state.json`)
```
idle ──> running ──┬──> idle (queue exhausted, no halts; ready for next run)
                   │
                   └──> halted (any goal halted; locked until human resets)
```

Once halted, NO AI can de-escalate. Only human-invoked `/agentic-dev:resume` flips back to running (or skip, abort, etc.).

## 5. Lifecycle: `_advance-goal <goal-id>`

```
1. Pre-check: queue has goal-id with status=approved
2. queue-set-status.sh <id> running + populate started_at + baseline_ref
3. Call /agentic-dev:_run-implementer <id>
   - Captures manifest at .claude/agentic/manifests/<id>.json
4. Call /agentic-dev:_run-gates <id>
   - Writes verdict
   - On overall=fail: queue-set-status halted; circuit-breaker.sh halted; escalation already generated by _run-gates → notify; exit 1
5. Call /agentic-dev:_run-reviewer <id>
6. Examine .claude/agentic/auto-fix-queue/<id>.json (if it exists from reviewer):
   - File exists → mechanical concerns only → enter auto-fix loop (max 2 rounds)
     - Round k: re-dispatch implementer with structured concerns as additional kickoff input
     - Re-run gates + reviewer
     - If reviewer-verdict.verdict == clean → exit loop, success path
     - If still mechanical-only and rounds < 2 → next round
     - If rounds == 2 and still concerns → escalate (auto_fix_exhausted)
   - File doesn't exist → reviewer returned clean or escalated already
7. On reviewer success (clean primary + clean adversary):
   - queue-set-status.sh <id> completed + populate completed_at + head_ref + manifest_path
   - circuit-breaker stays running (queue advances)
   - cleanup-completed-goal.sh <id> (removes worktree per umbrella §6.5)
   - Send digest notification
8. On any escalation:
   - queue-set-status.sh <id> halted + halted_at
   - circuit-breaker halted + halted_reason + halted_goal_id
   - Notification already sent by upstream skill
   - exit 1
```

## 6. `_run-orchestrator` (queue loop)

```
1. Pre-check: state.json's circuit_breaker.state in {idle, running}
2. Pick first goal with status=approved from queue.yaml
3. If no approved goal:
   - If queue has any drafted/intent_only: print "Queue idle; <N> drafts awaiting human approval"; exit 0
   - Else: print "Queue empty"; exit 0
4. Run /agentic-dev:_advance-goal <id>
5. On exit 0: ScheduleWakeup with brief delay; recurse to step 2 (next goal)
6. On exit 1 (halt): exit; circuit breaker locks
```

Wake-up cadence (per spec §16/§22): 30s between goals when running; idle when halted.

## 7. `/agentic-dev:start` (user entry)

```
Usage: /agentic-dev:start [--until <HH:MM | duration>]

1. Verify .claude/agentic/state.json's circuit_breaker not halted
2. If --until specified: store target wake-up cutoff in state.json
3. Set circuit_breaker.state = running
4. Invoke /agentic-dev:_run-orchestrator
5. On orchestrator exit: print final summary (goals completed, halted, etc.)
```

## 8. `/agentic-dev:resume` (after halt)

```
Usage: /agentic-dev:resume <decision> [args]

Decisions:
- resume         re-attempt the halted goal (clear halt, restart pipeline)
- skip           mark halted goal abandoned, move to next
- address        receive a concern-resolution context and re-attempt
- replan         re-engage drafter on the halted goal's spec
- abort          stop entire queue; status: completed but with halted markers preserved

Decisions are logged to .claude/agentic/decisions.log per umbrella §11.
```

## 9. Schemas

No NEW schemas in P6. Existing state.schema.json + queue.schema.json v0.2 cover all transitions.

Bash helpers use Python heredocs + jsonschema to atomically read-modify-write-validate.

## 10. Testing strategy

- **Deterministic**: `queue_set_status_test.sh`, `circuit_breaker_test.sh`, `cleanup_completed_goal_test.sh` (each runs the helper on hand-authored state, asserts post-state).
- **Structural**: SKILL.md tests for `_advance-goal`, `_run-orchestrator`, `start`, `resume`.
- **No agent-dispatch smoke** in P6 (would require running real implementer + reviewer which were verified in P3+P5); P6 is plumbing.

Zero `claude -p`.

## 11. Load-bearing properties

- **P6-L1** — All queue/state writes are atomic + schema-validated. No partial-write corruption on crash.
- **P6-L2** — Halted state can only be cleared by human (via /agentic-dev:resume).
- **P6-L3** — Auto-fix loop has hard cap of 2 rounds; exhaustion escalates.
- **P6-L4** — Cleanup-on-success only runs after BOTH primary and adversary reviewers approve.
- **P6-L5** — Wake-up cadence is configurable but defaults match umbrella §16 (30s between goals).
- **P6-L6** — Orchestrator never modifies a spec, manifest, verdict, or escalation packet — it only updates queue/state and dispatches lifecycle skills.
